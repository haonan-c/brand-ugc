# Domain Docs

本仓库采用单上下文领域文档结构。

## 开始探索前

在修改领域行为前，先读取：

- 根目录 `CONTEXT.md`；
- `docs/adr/` 中与当前工作相关的 ADR。

文件尚不存在时直接继续，不需要提前创建。`/domain-modeling` 在真实领域词汇或不可逆
决策形成时按需创建。

## 目录结构

```text
/
├── CONTEXT.md
├── docs/
│   ├── adr/
│   │   ├── 0001-example-decision.md
│   │   └── 0002-example-decision.md
│   └── agents/
└── ...
```

## 使用统一领域词汇

Issue 标题、规格、测试、模块和接口应使用 `CONTEXT.md` 定义的领域术语。不要为已定义
概念随意引入同义词。

如果所需概念尚未进入词汇表，应先判断：

1. 是否只是当前实现引入的临时术语；
2. 是否确实存在新的领域概念，需要通过 `/domain-modeling` 记录。

## 处理 ADR 冲突

如果新方案与已有 ADR 冲突，必须明确指出，不得静默覆盖：

> 与 ADR-0007 冲突，但建议重新讨论，因为……

只有新的 ADR 被接受后，才按新决策实施。
